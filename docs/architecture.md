# 架构与数据含义

## 转发

`generate_exports.py` 直接解析本机 x64 PE 导出表，仅使用 Python 标准库，生成 `.def`、导出名表和 MASM 跳板。普通导出保存 Windows x64 参数寄存器 RCX/RDX/R8/R9、XMM0–3，解析真实入口后恢复寄存器，再尾跳真实函数，保持原调用者栈参数位置。

`D3D11CreateDevice` 和 `D3D11CreateDeviceAndSwapChain` 由 C++ 显式转发。真实 DLL 使用系统目录绝对路径加载；不在 DllMain 中加载运行库或安装观察器。成功返回的设备/上下文用于安装观察器；纯转发模式跳过安装。

## 观察

观察器给对象创建私有虚表副本，仅替换选定槽，不修改真实 D3D11 的代码段，也不更改全局只读虚表。保留调用真实方法的地址，采样后仍执行原调用。

旧实验中只复制公开 Device5 的 69 槽导致 `GetFeatureLevel` 访问私有第 69 槽时崩溃。因此本版本保留连续可执行地址组成的尾部，上限 512 槽，不能确定边界时拒绝安装。这是对已遇到问题的兼容处理，不是公开 COM 契约，不代表其他运行时布局普遍兼容。

观察模式将自身模块固定到进程生命周期，保留虚表副本，避免对象仍存活时 DLL 卸载导致悬空函数指针。当前不提供运行中卸载钩子。设备/上下文接口别名与更老版本不强行接管。

## 数据路径

```text
目标程序 → 代理设备创建入口 → System32/d3d11.dll
                              ↓ 成功返回 COM 对象
                       对象私有虚表副本
                       ├─ CreatePixel/ComputeShader → DXBC
                       └─ Draw / Dispatch
                            ├─ 无请求：轮询，继续真实调用
                            └─ 有请求：查询立即上下文绑定 → JSONL → 继续真实调用
```

记录的是实际调用前的状态，字段包括线程、上下文类型、绑定 Shader、资源地址、纹理尺寸/格式/采样数、缓冲大小。采样有事件数上限，不通过 Present 切帧。不同上下文的记录按写日志的互斥锁顺序排列，不等于跨线程 GPU 执行顺序。

## 隔离与部署

- 根目录可配置，每个进程按 PID 和创建时间隔离，避免多实例抢同一 `capture.request` 和 PID 重用覆盖文件。
- 请求临时文件写完后改名；重复待处理请求拒绝覆盖。采样完成必须检查结束记录。
- 安装拒绝覆盖已有 DLL，卸载核对安装文件 SHA-256；不随项目复制游戏 DLL、贴图、Shader 包、原始游戏采样或加载器补丁。
- 原实验目录与现有测试包保持不变。这里的 `src/` 源于旧代理源码，并清除了针对旧目录的路径、异常诊断处理器和游戏进程管理脚本。

## 适合回答的问题

- 哪些 PS / CS 在当前场景被使用？
- 某组后处理在什么尺寸的目标上运行？输入 SRV 与输出 RTV / UAV 如何衔接？
- 相邻降采样/模糊/合成调用是否使用同一份字节码？
- 配合字节码与调试名，哪些调用可能属于亮部提取、模糊和合成？

推断应附对应采样事件、Shader 文件和反汇编证据。没有纹理内容、常量值和帧边界时，不能直接宣称已经完整还原渲染算法。
